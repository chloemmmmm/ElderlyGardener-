## 1. 产品概述

### 1.1 问题背景

中国 60 岁以上人口已突破 2.8 亿，脑卒中、骨折术后与慢性病导致的上肢功能障碍严重影响老人独立生活能力。居家康复可及性高，但长期坚持率不足 30%。

### 1.2 解决方案

康护园通过「园艺任务化」与「多模态即时反馈」，把枯燥的上肢训练变成老人愿意重复、康复师可远程管理的完整闭环：

- **C 端**：可穿戴园艺套件 + VR 沉浸式训练场景
- **B 端**：康复师远程管理后台，提供证据链与决策支持

### 1.3 价值主张

- **对老人**：在 VR 园艺场景中完成浇水、松土、摘果等任务，获得气动/震动/视觉反馈，提升依从性与动作质量。
- **对康复师**：在 B 端后台集中查看风险分层、训练记录与证据链，快速判断优先级并调整计划，保留最终决策权。
- **对产品**：以研究驱动设计，将 C 端训练数据与 B 端决策支持打通，形成可验证、可迭代的产品原型。

## 3. 用户与角色

### 3.1 康复治疗师（B 端核心用户）

负责 15–30 位居家老人的随访与计划调整。核心诉求：在每日有限时间内，优先看到「需要我出手」的对象与证据，而不是被海量数据淹没。

### 3.2 居家老人（C 端/VR 使用者）

65 岁以上，存在上肢功能障碍或认知衰退早期迹象。需要低认知负荷、即时反馈、有成就感的训练体验，并能获得家属/康复师的远程关注。

### 3.3 家属 / 照护者（协同角色）

协助老人佩戴设备、观察训练状态。需要简洁的训练反馈与异常提醒，避免成为主要操作负担。

## 4. 产品范围

### 4.1 In Scope

- B 端康复师管理后台：工作台、对象档案、计划管理、训练记录、数据看板、通知、搜索
- C 端可穿戴硬件原型：IMU + 弯曲 + 压力传感器，气动/震动反馈
- VR 园艺训练场景：浇水、松土、摘果三段任务与动作判定
- 传感器数据到 B 端的证据链呈现与 AI 辅助建议
- 可用性测试方案与迭代闭环

### 4.2 Out of Scope

- 真实临床级医疗器械认证（如 NMPA/FDA）
- 大规模硬件生产、供应链与售后体系
- 多机构 SaaS 租户、计费与医保对接
- 家属端独立 App（本阶段以康复师协同为主）
- 离线训练与本地长期存储

## 6. 非功能需求

| 维度 | 要求 | 验收标准 |
|------|------|----------|
| 无障碍 | B 端与 VR 端均需考虑低视力与低数字素养用户 | 键盘可达、对比度 ≥ 4.5:1、关键信息不依赖颜色 alone |
| 性能 | B 端首屏加载 ≤ 3s，列表页翻页无感知加载 | Lighthouse Performance ≥ 70 |
| 可靠性 | 训练数据不丢失，传感器断连可恢复 | 断连 30s 内重连，本地缓存关键动作数据 |
| 安全 | 对象健康数据加密传输与存储 | HTTPS、敏感字段脱敏、操作日志 |
| 可维护性 | 前后端接口清晰，数据模型可扩展 | 接口文档覆盖核心 CRUD，版本化 Schema |

## 7. 数据模型

- **Therapist（康复师）**：id、姓名、机构、角色、联系方式、偏好设置
- **Client（康复对象/老人）**：id、姓名、年龄、诊断、康复阶段、风险标签、ADL 基线、照护者信息、关联 Therapist
- **Plan（训练计划）**：id、clientId、阶段目标、起止时间、版本历史、变更记录、状态
- **Exercise（训练动作）**：id、planId、动作类型、目标角度/力度/次数、启用状态、园艺映射
- **Session（训练记录）**：id、clientId、planId、开始/结束时间、完成状态、动作表现、AI 摘要、人工备注
- **Notification（通知）**：id、recipientId、类型、标题、内容、目标链接、已读状态、创建时间

## 8. 体验原则

- **Evidence First**：优先展示需要行动的信号，而非总体 KPI。
- **Human Control**：AI 只整理事实与建议，不会自动改写训练计划。
- **Visible Uncertainty**：区分系统事实、用户自述、数据缺失与 AI 推测。
- **Traceability**：每一次计划变更、人工备注与 AI 建议都保留来源与操作人。

## 9. 路线图

### Phase 1 · 概念验证（0 → 1 可运行原型）

- 完成 C 端硬件原型一代（传感器 + 反馈）
- 完成 VR 园艺场景 MVP（1 个任务流程）
- 完成 B 端后台核心闭环：工作台 → 对象 → 计划 → 记录

### Phase 2 · 试点验证（小样本可用性与有效性测试）

- 8–12 名康复师访谈与 B 端可用性测试
- 8–15 名老人参与 C 端/VR 训练试点
- 证据链时间线、计划 diff 视图完整落地

### Phase 3 · 临床合作（工程化与合规准备）

- 与社区康复中心/医院建立合作
- 动作判定算法小样本验证
- 数据安全合规、多机构权限、计费对接评估

## 10. 风险与开放问题

- **研究真实性**：当前用户画像、可用性测试与部分数据为演示样例，需补充一手访谈与试点数据。
- **硬件工程**：传感器与 VR 渲染的同步精度、老年人晕动症风险、长期使用舒适性需工程验证。
- **临床合规**：作为涉及健康数据的系统，需明确医疗器械分类、数据隐私与伦理审批路径。
- **商业模式**：面向机构（B2B）还是面向家庭（B2B2C）尚未验证，需后续市场调研。
- **技术栈**：VR 引擎（Unity / WebXR）、后端服务、硬件通信协议需在原型阶段选型并验证稳定性。
